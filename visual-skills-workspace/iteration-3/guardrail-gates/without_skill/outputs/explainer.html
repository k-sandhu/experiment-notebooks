Mini lesson · AI safety guards

"Starts with the right folder" is not a lock

AI helpers can now act on a computer: read a file, write a report, delete a scratch file. Before each action runs, a small piece of code called a gate decides yes or no.

AI helperasksgatedecidesfile
A popular shortcut: if the file path starts with the allowed folder, say yes.
Sounds safe. In this lesson you will fool it five ways, then see what a safer gate does.

About 3 minutes. All numbers come from a test of 22 written requests and 5 gate designs (notebook 10).

Step 1 · The rules

The helper's house rules

A file's path is its address: folder names joined by slashes, like a street address read from the top down. The helper works in one project folder, /workspace/acme.

  • Read any project file, except secret ones such as .env (passwords live there).
  • Write only inside output/.
  • Delete only inside tmp/, one file at a time, with a trusted approval.
  • No running commands, no internet.

Step 2 · The starts-with gate

A gate that reads only the beginning

Step 4 · A safer gate

Check where it goes, not how it's spelled

The safer design in the test (called scoped capabilities) adds three habits:

1
Follow the path first. Walk every .. and every shortcut to the real destination, in order, before judging.
2
Compare whole folder names. tmp-other is not inside tmp, even though the letters match.
3
Keep secret names locked. Refuse files like .env, .ssh, credentials, payroll even inside the project.

It also offers only three tools (read, write, delete), so there is no "run a command" button to ask for.

Try both gates. Pick a path, or edit it.

Step 6 · Reading the result fairly

What this test does and does not show

The starts-with gate let through every request built to beat a text check. It stopped the other forbidden ones because they started outside the folder or asked for a command or the internet. So this is a list of tricks it misses, not a failure rate.

The safer gate's perfect score is by design. The same person wrote the requests and the gate from the same rules. It shows which known tricks each design catches, not how often real attacks succeed.

Not tested: hard links, a shortcut swapped between the check and the action, real disks with many links, and escaping a sandbox. The 22 requests are hand-written, so there are no error bars.

Takeaway
Judge a file request by where it ends up, not by how its address begins.
Follow every .. and shortcut, compare whole folder names, lock secret files, and offer only the tools the job needs.
