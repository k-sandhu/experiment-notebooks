# invoice-checks: facts (econ/21-verification-costs)

Source folder: econ/21-verification-costs (README.md, data/case_results.csv, break_even.json, cost_scenarios.csv, summary.csv, verification_summary.json). Numbers re-derived from data.json where noted.

## Question
When a cheap model's invoice answers are checked before payment (by asking it a second time, or by a stronger model reviewing), and failed checks go to an expensive model, does that cost less than using the expensive model on every invoice? How expensive must the expensive call be (the "break-even price") before each check pays for itself? (README "The question")

## The models and routes
- Cheap model: Qwen3.8 Flash (open weights, OpenRouter, reasoning off, ~USD 0.15/M input tokens). Expensive/fallback: GPT-6.1 Sol via `codex exec` (price per call is ASSUMED: subscription reports no charge). Checker: Claude Opus 5.5 via `claude -p` (cost = list price). Person review: assumed USD 1 per invoice, always right, not actually run.
- Routes (code names): Qwen direct; GPT direct; Qwen repeat + GPT (accept Qwen's first answer if a second separate Qwen call matches decision and cents, else GPT); Claude screen + GPT (accept if Claude accepts, else GPT); Claude screen + review (rejected go to a person).
- Data: 72 test invoices generated by code (12 more were a trial run), exact answer from two rule programs that agree on all 84. 14 should be HOLD (6 duplicate or blocked-supplier invoices plus 8 invoices whose payment-limit exception is expired or not yet signed), 58 should be PAY an exact amount. An answer is right only if decision AND amount match to the cent.

## Headline numbers (summary.csv, case_results.csv; checked equal)
- Qwen direct: exact on 14/72 (0.194; Wilson 95% 0.120-0.300), all 14 are holds; 0 of 58 payable right (floor). Mean underpayment exposure USD 922.66/invoice, overpayment USD 7.36. No unreadable replies.
- GPT direct, Qwen repeat + GPT, Claude screen + GPT: 72/72 exact (ceiling; Wilson lower bound 0.949). Claude screen + review: 14 paid automatically (coverage 0.194), 58 sent to a person (unresolved).
- Both checks accepted exactly the same 14 holds, rejected the 58 wrong answers, no missed mistake, no wasted escalation (verification_summary.json). GPT calls: 58 per check route vs 72 for GPT direct, saving 14/72 = 0.1944 GPT calls per invoice.
- Break-even GPT price (zero loss; break_even.json, recomputed from case_results.csv, match): Qwen repeat + GPT USD 0.001119 (about 0.0011); Claude screen + GPT USD 0.133204 (about 0.1332). Formula: (extra known model cost per invoice) / (GPT calls saved per invoice): 0.0002176/0.1944 and 0.0259/0.1944.
- Cost per invoice at G=0.05, 1% overpay loss, 0.1% underpay loss (cost_scenarios.csv): Qwen direct 0.9964; GPT direct 0.0500; repeat+GPT 0.0405 (diff -0.0095, CI -0.0144..-0.0053); Claude screen+GPT 0.0662 (+0.0162, CI +0.0109..+0.0209); Claude screen+review 0.8315.
- Straight line in G (data.json cost_lines): cost = known + G*gpt + H*review + a*over + b*under. For the check routes losses are zero, so cost = intercept + slope*G: repeat+GPT 0.0002176 + 0.8056 G; Claude screen+GPT 0.0259 + 0.8056 G; GPT direct 0 + 1.0 G. Lines cross where 0.1944 G = extra cost. This reproduces all 60 rows of cost_scenarios.csv (max error 1e-14).

## Definitions
- Escalation: sending a doubtful invoice to the expensive model (one full GPT call). Missed mistake: check accepts a wrong answer. Wasted escalation: check rejects a right answer.
- Break-even price: the GPT price per call at which a check route costs the same as GPT alone; above it the check saves money.
- Unreadable reply: not parseable (counted apart from wrong). Three Claude checks (test-013, test-025, test-061) wrote working before the JSON; retried, cost USD 0.0592 total.

## Illustrative worked example (made-up, README intro, NOT measured; also in data.json)
100 invoices; expensive assistant USD 0.10 each (USD 10 for all); cheap answer + check USD 0.02 each (USD 2). Check accepts 30 right answers -> saves 30 x 0.10 = USD 3, net +USD 1. If expensive costs 0.05: saves 1.50, net -0.50. Break-even = 0.02/0.30 = about USD 0.067. If it also accepted 2 wrong answers costing USD 1 each, extra USD 2 cost raises the break-even.

## Concrete invoices
- test-002 (mixed, end-to-end): exact PAY USD 1,171.39. Qwen call 1: 14567 cents; call 2: 5913 cents (differ, so repeat check escalates); GPT 117139 (right); Claude rejects with the recalculation. Qwen alone underpays by USD 1,025.72.
- test-012: a hold (exception signed day 31, today day 30; amount before hold USD 1,785.54, limit USD 100). Qwen, GPT, Claude all agree HOLD; one of Qwen's 14 exact answers.
- test-001 (ordinary): exact USD 743.31; Qwen 678.95 and 672.53 (short 64.36, one of the closest misses; checks caught it). test-055: authorised 410.25, Qwen 346.79/349.17.
- test-004: authorised USD 1,249.80; Qwen 138.95 and 127.53. USD 138.95 was Qwen's answer on 4 invoices with authorised amounts USD 1,022.37-2,324.91 (test-004, -042, -044, -047): amounts did not track the invoice.
- test-043: Qwen overpaid USD 403.86 (answered 1,269.58 vs 865.72); second call 1,265.98, near agreement but not to the cent.
- test-031: Qwen misread ("zero eligible units") and answered USD 6.28 (shipping only) vs correct USD 706.75.

## Caveats (README sections 11, summary)
- GPT price per call is unknown (assumed range 0.005-0.25); Claude cost is list price; loss on wrong payments is an assumed fixed share (overpay 1%, underpay 0.1% in the running example; underpay always 1/10 of overpay, no reason recorded); person review assumed perfect at USD 1.
- The checks never met a hard mistake: both at ceiling (72/72 decisions); the test cannot rank them on accuracy. Repeat check works only because it requires agreement to the cent (within USD 1 it would have paid 8 wrong answers).
- Qwen ran with reasoning off, no calculator; invoice mix chosen by design from one generator; a rules program gets all 72 right.
- Break-even prices are assumption-free only because losses are zero for the check routes in this run.
- Wording note: README says Qwen's `automatic` answers: in case_results.csv Qwen direct has automatic=True on all 72 but correct on 14.
