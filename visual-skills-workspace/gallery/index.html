Explainer Skills Lab

Seven agent skills for turning a finding, a process or a dataset into an animated, interactive explainer that a newcomer can follow on a phone. They grew out of the chalkboard animations of an agentic finance harness and a lesson on deep work versus parallel agents.

To test them, the same model built five explainers from this repository's experiment data with the skills and without them, and a separate model compared each pair blind. After each round, the reviews' complaints went into the skills and the five were rebuilt, always against the same versions made without the skills. Round 4 and the no-skills versions are live below, side by side, with the earlier rounds' versions one click away. Eight more notebooks built with the skills follow.

The skills

  • explainer-directorFinds the one message, picks the form, writes a storyboard with one idea per step.
  • explainer-kitEngine, four styles, scaffold, render check at phone and desktop widths, GIF/MP4 recorder.
  • stepper-lessonKhan Academy style lesson: Next, short captions, one or two steps the reader plays.
  • system-replayRecorded runs replayed on a timeline you can pause and scrub, or a designed walkthrough.
  • explorable-modelA live model the reader steers with a slider; the break-even point is marked.
  • unit-storyEvery item is a dot; dots regroup by outcome; small samples show their uncertainty.
  • predict-revealThe reader commits a guess, then the real data animates in against it.

More experiments

Eight more notebooks, each built once with the revised skills from the notebook's README and data, with no human edits. Tap a card to open it full size.

What four rounds of reviews taught

Across four rounds the version with the skills won 13 of the 20 blind comparisons (3, 2, 3, then 5 of 5). Its summed review score was higher in every round: 110 to 105, 109 to 103, 112 to 100, then 113 to 100 out of 125. The skills made layout reliable: 54 of 55 automatic checks passed in each round with them, against 48 of 55 without. The replay and the forecast won all four rounds.

The round-3 changes, tested in round 4:

  • One question per case, with "Right" or "Not quite" feedback that depends on the pick. Followed: the guardrail lesson now quizzes four tricks one at a time and walks a dot to where each path really ends. It won for the first time, 22 to 21.
  • A social-feed visual is a fixed-size card that reads without tapping and shows a control result. Followed: the SQL visual is now a looping 4:5 card that shows the models still answered ordinary questions (10 of 11 got 23 of 23). It won for the first time, 22 to 21; the reviewer named legibility at phone width as the deciding point.
  • Compute every derived number in code. No arithmetic errors were flagged in the versions with the skills this round; the round-3 SQL version had shown 3% where the right figure is 2.1%.

The guardrail and SQL wins are by one point each, as is the invoice win, and the reviewer moved the unchanged no-skills guardrail page from 23 to 21 between rounds. So round 4 shows that the two cases that lost three times are now level, not that the skills are clearly better on them.

How far to trust this

Each case was built once per condition in each round, and all four rounds reused the same no-skills versions, so the 13-of-20 result could easily swing either way with more runs. The reviewer is also a model, and it scored the same no-skills page differently from round to round (the guardrail page got 23, 23, 23, then 21; the invoice page 21, 21, 19, then 21), so differences of one or two points are noise. Read the comparison as a map of what the skills change, not a measurement of how much.

The skill files contain no data or wording from the five test notebooks, so the runs with skills could not copy an answer. The pages here are copies of each run's output, unedited.
