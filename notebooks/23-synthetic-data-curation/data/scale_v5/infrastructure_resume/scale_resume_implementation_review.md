# Scale continuation implementation review

The continuation helper passes an independent read-only review at source SHA-256 `62d55e98fd877d518c187650caaf9fbbde3c01cdd86da15d65d276352cecd7ef`. The accompanying mocked-test file matches SHA-256 `02d63e62c5ce1836f9bf01a3e090a915785cb01104600b33a37397e6373daf84`. The parent reports all 13 mocked tests pass; I inspected the test source but did not run it. This review made no data changes and no model calls.

The final helper checks the full prior cache inventory key by key against each compressed cache file's raw SHA. It requires the inventoried prefix to be complete and settled, rejects missing or modified prior caches, and allows later cache keys so the completed notebook can replay offline. The approved capacity failure must be a pre-inventoried request whose original case, source hash, prompt input hash, profile, request plan and archived stop all match. Its only allowed outcome is the cached terminal capacity failure with return code 1 and no completed turn or usable model output. The dispatch wrapper only bypasses that exact cached row. A different error settles its current worker wave, writes a separate stop receipt and prevents later waves.

The helper also binds the main-start declaration, protocol, allocation and listed request-plan bytes; it checks that the continuation declaration follows all inventoried attempts. Existing validation artifacts are diverted to separate diagnostics during replay, and live collection is blocked after originals are complete. The explicit namespace and offline-by-default CLI path support notebook replay without changing the frozen runtime helpers.

The amendment must include `protected_files` for `main_start_declaration.json`, `main/protocol.json` and `main/allocation.json`; all pre-continuation `request_plans`; and a complete `cache_inventory` with `protocol`, `count`, and `requests: {request_key: raw_cache_sha256}`. It must also identify the original stop and byte-exact archived stop, plus each individually reviewed failure with its exact cache SHA, source/input hashes, error, stop SHA and original request profile. `declared_at_utc` must be later than the completion timestamp of every inventoried cache attempt.

One execution-binding detail remains external to the helper: its `implementation` provenance field is optional, and the helper cannot prove that notebook-embedded code is byte-identical to the file whose hash is recorded. The pre-call declaration should therefore bind both helper and test SHA values above, and the actual CLI/notebook should use those reviewed bytes. This is an amendment/provenance requirement, not a blocker in the reviewed continuation behavior.
