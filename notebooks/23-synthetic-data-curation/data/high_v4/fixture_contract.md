# V4 procurement fixture contract

Created 2026-10-26. This date records fixture creation, not historical business activity. Cutoff is 2026-10-26T12:00:00Z, inclusive. No model calls are made. Earlier sources, responses and helpers remain frozen.

## Purpose and API

A fictional purchasing team reconciles one order line against approved commercial changes, effective-dated handling factors and allocations, price schedules and movement histories. A second line has the same SKU; SKU equality does not merge demand accounts.

The standalone module imports only the standard library, with no repo imports or __file__ dependency. Public names are HIGH_VERSION, HIGH_FIELDS, HIGH_FAMILIES, HIGH_CUTOFF, HIGH_TASK_INSTRUCTIONS; high_make_cases(n, seed, level=1, split='pilot', start_index=0); high_parse_document(document); high_independent_reference(case); high_calculation_trace(case); high_correct_response(case); high_validate_answer(case, response); high_audit_fixtures(cases); high_make_verifier_controls(cases).

Case dictionaries retain case_id, family, level, round, arm, split, created_at, document, gold, evidence_gold, source_record, template_group, content_hash, semantic_hash. Zero cases are supported. Levels 1/2/3/4 contain 32/64/128/192 logical SH-* shipments, plus order/line distractor shipments, return/reversal events and extra ingestion revisions/copies. These base counts exclude control events and distractor shipments. Split is pilot, collection or audit.

The six family labels are scenario variants, not isolated causal ablations. They share most accounting features: shipment_revisions, dated_uom_returns, split_allocations, tier_sequential_pricing, effective_authority, compound. Audit changes heading format, not semantic families. Opaque IDs do not disclose family, level or split. semantic_hash normalizes source-table ordering and exact duplicate copies while preserving distinct values. It identifies equivalent source facts, not arbitrary different histories producing the same answer.

Models receive only instructions, case ID and document. Gold, source_record, family, level, evidence_gold and calculation traces are evaluator-only. Cases are generated by deterministic code and table renderers; no model writes individual source cases.

## Sources and exact business rules

P01 is the signed order/defaults/status, P02 the field-level approval register, P03 the UOM master, P04 dated allocation schedules, P05 the pack-price schedules, P06 movement history. The visible header also identifies order, target line/SKU, other order, issue time and cutoff. Every source_record field is rendered and parsed, including obsolete, duplicate, irrelevant and excluded rows.

Resolve each commercial field independently. A row qualifies only if approved and both recorded/effective timestamps are at or before cutoff. Priority is line scope before order default, then higher authority, later effective timestamp and higher revision. Recorded time filters availability only. Partial changes retain unstated values. Finalists must have one unique value.

For each physical event, select its highest revision recorded by cutoff, counting exact ingestion copies once. Only then test state/order/occurrence. Selected VOID or future-occurring rows never fall back to an old revision. Active reversals remove the referenced logical shipment once; VOID reversals have no effect. Returns on inactive shipments contribute zero.

For an active shipment, select both SKU/UOM and allocation versions at its selected occurrence date. Convert handling quantity to individual units and multiply the target-line share. A return uses the referenced selected shipment's SKU/UOM/date/allocation key and those original-date versions, irrespective of return date. Subtract its positive returned magnitude from dispatch. Individual-unit contributions are exact integers; shares total 100%; accepted returns cannot exceed the selected shipment quantity.

Open units equal approved ordered demand minus net allocated dispatch. Price tiers use that ordered demand BEFORE movements. The exact per-unit cents are:

    gross_cents / pack_units
    * (1 - rebate_a_bps / 10000)
    * (1 - rebate_b_bps / 10000)
    + fee_cents
    + pack_fee_cents / pack_units
    - credit_cents

The gross price is for an entire price pack. Tier rebates are sequential; per-unit fees/credits and converted pack fee are after rebates. Retain exact precision and round once at the final unit amount to the nearest integer cent, exact halves up. Warehouse CASE/BOX factors and pricing pack_units serve different purposes.

All generated orders remain active. Shipment VOID, REVERSAL and RETURN are not order cancellation. Cancelled/ambiguous remain valid schema options only for compatibility, not observed v4 gold classes.

## Material solvability and independent checks

Constructor gold uses procedural term application, a latest-row map and Decimal arithmetic (70-digit price context). A separately implemented reducer groups candidates/rows, uses Fraction arithmetic and an integer half-up formula. high_independent_reference and high_calculation_trace start from parsed rendered text, without reading source_record or stored gold.

The parser requires exactly one of each header/default/table, complete column names and row widths, typed integer/approval cells and consistent repeated plan attributes. The full parsed record must equal original source_record. Sorted-key JSON save/reload must preserve the document, hashes and complete facts.

Audits check unique target/line/approval/master/tier identities, 100% allocation shares, valid movement kinds/states/timestamps, conflicting same-event/revision copies, existing same-order/SKU shipment references, return bounds, unique current commercial values, applicable dated rates/shares, integral contributions and nonnegative outputs. The trace includes selected revision, exclusion/inclusion reason, conversion/allocation dates/factors/shares, signed per-event units, term winners and exact rational price steps.

The two reducers share explicit business rules; agreement does not independently establish those rules' real-world appropriateness. A separate reader must review instructions and visible sources before live calls. The tests also check instruction/P05 agreement on pack pricing and converted pack fees, not merely numerical reducer agreement.

## Evidence and scoring

Response is exactly {case_id, answer, evidence}. Answer and evidence each have the seven existing fields. Integers reject booleans. Extra keys, invalid dates/types, repeated evidence IDs and unknown sources fail schema/evidence checks. Wrong values and evidence-only failures are separately categorized.

Citations identify whole source groups. Extra P01-P06 context is harmless. Quantity requires the current demand source plus P03/P04/P06. It does not force redundant P01 when current demand is in P02. Price needs P05 and the current demand/plan sources. SKU/status require P01; order ID can use P01/P02/P04/P06 in packet context. Currency/date require their current value-bearing group. Report values and citations separately and inspect observed citation-only rejects before recommending exports.

The default feedback is failed field names only. Exact truth, traces and expected values do not enter generation, repair or fresh retry prompts. Richer reminders require a separately frozen parent-approved protocol.

## Hand-calculated verifier control

This small test record is an evaluator control, not a measured model case. Selected shipment S1 is 12 CASE on the old date: 24 units/CASE at 25% allocation gives 72 target units. Its later 4-CASE return uses that same historical rate/share: -24 units. S2 is reversed, S3's selected revision is VOID, S4 contributes 8 EA at 50%: 4 units. Net dispatch is 52, so 1,000 ordered units leave 948 open.

A 12,000-cent price pack of 24 units gives 500 cents/unit. Rebates of 10% then 20% leave 360 cents. Add 1.25 cents/unit plus a 6-cent pack fee /24 = 0.25 cents/unit, subtract a 0.50-cent unit credit: final 361 cents. Another control requires exactly 100.5 cents to round to 101.

## Verification and limits

Run python -m unittest test_high_fixtures -v from authoring. Seventeen substantive tests pass at prototype completion: all six families/four levels, sorted-key JSON/source roundtrips, audit headings, deterministic identities, tampered sources, exact hand equations, instruction/price-unit agreement, revision/cutoff ordering, duplicate/reversal idempotence, historical return conversion/allocation, partial approval precedence, ordered-versus-open tiers, half-up without intermediate rounding, structural mutations and schema/value/evidence separation.

Six-family smoke tests produced 2,749-2,932 words at level 1; 4,217-4,312 at level 2; 6,931-7,026 at level 3; 9,645-9,740 at level 4. Measure actual request/token budgets separately.

These are clean, documented fictional integrations. Real authority, tax, return, credit and allocation policies vary. No OCR, malformed source rows, partial reversals, hidden contracts or order cancellations are included. The experiment measures reconciliation under these rules, not broad accounting competence. Longer sources and dependencies do not guarantee errors or any repair advantage. Sampling, model effort, pilot selection, live budgets and the paired fresh-retry control belong to the separately frozen execution protocol.
