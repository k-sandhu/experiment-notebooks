Astra-generated weights: what works, what fails, and whether decoding helps

Exploratory diagnostic study • November 2, 2026 • Original weights preserved • No training or fresh LLM requests

The successful classifier looks like a compact numerical program. The SQL transformer also has a highly engineered weight pattern, but its output scores are so small that ordinary softmax becomes uniform. Standard decoding controls changed its text without recovering the requested table and columns.

A weight is a number used inside a network's calculations. The same architecture can implement useful or useless functions depending on those numbers. Looking for a familiar histogram is therefore only a first check: the important questions are which function the numbers compute and whether the resulting scores support the intended decoding procedure.

This study examines the 388 values Astra supplied for the two-hidden-layer ring classifier and the 2,208 editable values it supplied for the one-block SQL transformer. It also measures one real pretrained language-model checkpoint as a distributional reference. The reference is not a SQL benchmark or a universal template for how all LLM weights should look.

1. What was measured

The SQL checkpoint is Astra attempt 2 at xhigh. Its original greedy outputs on 16 schemas were reproduced exactly before the sweep. All 123 existing synthetic schemas were then evaluated under 11 fixed decoding conditions, producing 1,845 outputs. Sampling conditions use three seeds per schema; other conditions use one. The 16 inspected schemas and the 12 examples Astra received as feedback are not a blind benchmark. The additional 107 schemas broaden this diagnosis.

Every SQL condition uses the same frozen checkpoint, float64 arithmetic, up to 32 new tokens and a 64-token context limit. The tested controls do not contain a SQL grammar, a query template, a schema-copy routine or a replacement-name rule. The checkpoint hash remained unchanged. Each generation and full request is cached in data/generations/; derived whitespace cleanup reuses the raw greedy output. Repetition and sampling processors come from Transformers 4.55.0; four-beam search is implemented in the tester using normalized log probabilities and length normalization. The same three sampling seeds are reused across schemas for paired comparisons, so the 369 sampled outputs are not 369 independent random streams.

SQL text was parsed with SQLGlot's SQLite dialect. A readable result means exactly one parsed SELECT. A schema match additionally requires the requested table and the requested column names in order, as plain column projections without filters or other extra clauses. No tables were created and no SQL was executed. Parser acceptance does not establish SQLite executability or correct returned rows. Parser failures and readable wrong answers are reported separately.

The independent reference is EleutherAI/pythia-14m, revision cf967c0a9a04383db6f7b1108d86b2962634b4ac, Apache-2.0, stored in FP16. Its 14,067,712 checkpoint values include large embedding tables; the comparison below uses the 1,189,888 non-embedding values. Only its weights were read; it was not used to generate text. Pythia is an open research suite designed for studies of training and scaling. Biderman et al. (2023).

The SQL values span 50.7 orders of magnitude. Its projection has RMS scale about 10⁻²⁴, while attention and feed-forward tensors contain values up to 10²⁰ and 10²². Its positional embedding RMS is about 10⁻¹³. The successful MLP instead has nonzero magnitudes from about 0.007 to 6, and only 63 distinct numeric values.

The trained reference is almost entirely dense: only two of its 1,189,888 core values are exactly zero. All 24 of its core matrices have full numerical rank, while the MLP's W2 and W3 have ranks 2 and 1. This is a measured contrast between these checkpoints, not a requirement for competence. The MLP demonstrates that a sparse, low-rank construction can be an excellent solution to a structured task.

There is no universal “healthy LLM weight histogram.” In a ReLU MLP, multiplying one neuron's incoming weights and bias by a positive constant and dividing its outgoing weights by the same constant preserves its function; magnitudes can therefore differ between equivalent networks. Permuting hidden units also preserves their function while changing their coordinate layout. Git Re-Basin (Ainsworth et al., 2023) studies such permutation equivalences. Large-model research also finds important activation outliers; these should not automatically be clipped as errors. LLM.int8() (Dettmers et al., 2022). That activation result does not establish that this SQL model's enormous weight scale is useful.

The setup also differs from editing a pretrained LLM. The original weight-space-programming report distinguishes constructing small networks from scratch from modifying an already-trained Qwen language model. Our SQL experiment supplies frozen word vectors but asks Astra to construct the autoregressive computation itself. GloVe (Pennington et al., 2014) learns word representations from word co-occurrence; it does not supply this transformer's sequence-generation behavior.

3. The MLP can be interpreted as a radius estimator and three thresholds

The first matrix has 14 nonzero unit-length directions and two unused rows. Its second matrix repeats two groups of columns, giving it numerical rank 2. Its output rows are, to within 1e-16, 0, 1, 2 and 3 times one vector. This means the output layer essentially uses a single scalar feature, which numerical probes identify as an estimated radius.

Writing that scalar as s(x), the four scores are approximately 0, s−0.249999616, 2s−0.749997887, 3s−1.499994685. Adjacent scores cross at estimated radii 0.249999616, 0.499998271, 0.749996798, very close to the task boundaries 0.25, 0.50 and 0.75. This is a functional explanation obtained from the emitted weights, not a claim about Astra's private reasoning.

On 36,000 angles around the unit circle, the inferred radius lies between 0.999975456 and 1.000000000. Its largest sampled relative error is 24.54 parts per million. Zero hidden biases make this feature positively homogeneous: scaling a nonnegative input radius scales the feature by the same factor. This supports the radius interpretation across radii, although finite angular sampling is not an exhaustive proof.

The original tests gave 20,000/20,000 balanced random points correct and 125,601/125,625 grid points correct. All 24 grid errors occurred at the specified class boundaries within 3×10⁻¹⁷, where tiny approximation and floating-point differences can change the selected side. The random test is at a ceiling, so it cannot resolve small differences among equally successful constructions.

A post-hoc stress test deliberately sampled within 10⁻⁵ or 10⁻⁶ of the three boundaries, using 3,600 angles per boundary/offset pair. It produced 34,784/43,200 correct classifications (80.52%). This sample is intentionally concentrated on difficult slivers and is not an estimate of ordinary input accuracy. It confirms that the measured 100% random-sample score is not exact correctness everywhere. The offsets were fixed before this stress test and no weights were changed.

4. The SQL head has a global score-scale problem

The effective vocabulary matrix is F = frozen_GloVe @ projection. The same F supplies the input vectors and output classifier. Sharing embeddings is a legitimate language-model design: Press and Wolf (2017) describe training tied input and output embeddings. Our frozen-vector/shared-projection construction is a much stronger restriction than co-training those embeddings.

In the current checkpoint, all final LayerNorm gains are √10⁻⁵ ≈ 0.003162 and the final biases are zero. A width-8 normalized vector has L2 norm below √8, so the final hidden-state norm is bounded by 0.00894427. Combining this with the largest effective output-vector norm gives an absolute logit bound of 6.89e-25, for every input sequence. This follows from LayerNorm's definition and the Cauchy–Schwarz inequality.

The first observed logits are around 10⁻³³. At ordinary temperature, softmax produces exactly 1/1,110 ≈ 0.0009009009 for every token in our float64 measurements. The head's bound is far below machine epsilon near 1, so ordinary exponentiation cannot resolve those differences. The correct-query token likelihood is correspondingly uniform. Greedy argmax still compares the tiny unnormalized scores directly and can therefore emit structured-looking fragments such as SELECT and FROM.

All three LayerNorm gains equal √epsilon. For vectors with variance much smaller than epsilon, this makes LayerNorm approximately subtract the mean without changing the scale. Combined with sparse huge/small coefficients, this is consistent with an attempt to program numerical gates. That is an interpretation of the weights, not confirmation of the author's intent. We did not reverse-engineer every gate.

An independent implementation of the specified forward equations agreed with the GPT-2 scaffold to a maximum 1.03e-07 relative to the largest logit, across 16 prompts. The original 16 generated outputs were reproduced exactly. This makes a simple tensor-order or transpose mistake less likely. Float32 generated identical token sequences on 15/16 cases, so higher precision alone has not been shown to fix the task.

Float16 is a separate portability problem: direct conversion overflows 105 SQL values and rounds 792 nonzero values to zero. The original task explicitly requested float64, so this is not a failure of that contract; it is evidence that ordinary FP16 deployment would require additional work. The MLP has neither representability problem under this check.

5. Standard decoding controls do not repair schema binding

Repetition penalties, no-repeat n-grams, sampling parameters, beam counts, suppressed tokens and stopping strings are common generation controls documented by Hugging Face Transformers. They change how scores become text. They do not create a learned association between an input table name and the output identifier.

Raw greedy produces a parser-accepted SELECT on 95/123 cases (77.24%), but all of those readable queries use the wrong schema or projection. The task score is 0/123. Reporting only parse acceptance would seriously overstate its usefulness.

Whitespace trimming and stopping after a semicolon leave the result unchanged. A repetition penalty of 1.2 reduces parser acceptance to 76/123. Blocking repeated trigrams reduces it to 30/123, even though it causes more EOS stops and less adjacent repetition. Stopping and non-repetition are not substitutes for selecting the right identifiers. Repeated quotation and separator patterns can be necessary in code, so hard n-gram bans deserve particular care.

Ordinary sampling and unscaled beam search operate on essentially uniform token probabilities here. A separate diagnostic multiplies logits by the inverse first-prompt logit standard deviation, about 1.08e+33. This is a fixed output-score scale change, equivalent to an exceptionally small positive temperature. It was chosen from score magnitude, not tuned on correctness, and leaves all greedy rankings unchanged. This scale restoration is distinct from fitting a temperature to calibrate statistical confidence. The rescaled conditions remain at zero schema matches. Scaling can make relative scores visible to probability-based decoding; it cannot correct their ordering.

6. Postprocessing that is reasonable to use

  • Keep harmless cleanup: trim outer whitespace, decode special tokens consistently, stop on EOS and optionally a completed statement delimiter. These are useful output-hygiene controls; this checkpoint's scores did not improve under them.
  • Use repetition controls cautiously: the tested penalty and n-gram bans reduced some repetition but did not improve the task, and they lowered parser acceptance. A penalty applied to the full prompt can also penalize the very names the model should copy.
  • Address output-score scale before sampling or beam search: this model requires a special calibration because its logits are extraordinarily small. A positive scalar preserves greedy argmax. This is not a recommendation to use a temperature near 10⁻³³ on ordinary pretrained models.
  • Parse and reject invalid output: validation can prevent downstream use of malformed SQL. It should report a failure rather than silently substitute different names. It adds reliability checks, not model competence.
  • Consider grammar-constrained decoding as a separate experiment: PICARD (Scholak et al., 2021) rejects syntactically inadmissible SQL continuations during decoding. It is a standard research-backed direction, but supplies external language rules. Restricting names to the supplied schema adds task knowledge too. Such results should be labeled separately from the unassisted network. No grammar constraint was used in this study.
  • For the MLP, keep argmax for class decisions: softmax is optional for displaying scores as a distribution and does not change the winning class. Positive temperature scaling also preserves that winner. If calibrated probabilities are required, evaluate them on a separate labeled calibration set. Guo et al. (2017) study post-hoc temperature calibration.

Blanket normalization or clipping of the SQL weights would alter the numerical program. It is not ordinary text postprocessing and was not done. A useful next feedback message to the weight author would give the measured logit bound, the uniform softmax result, the canonical identifier ranks, and concrete wrong input/output pairs. The tester should continue to leave candidate weight selection to the separate model.

7. Limits, saved evidence and reproduction

This is one emitted SQL checkpoint, one emitted MLP, one trained reference and a small synthetic schema set. It cannot establish a universal distribution for trained LLM weights or a general limit on Astra's ability. It is exploratory: the failure outputs were known before the diagnostic plan was written. No condition achieved any correct schema matches, so the sweep sits at a task-score floor and cannot rank general SQL competence. Parser validity is informative about formatting only.

The reference differs in width, number of layers, architecture, training, parameter count and precision. Half-precision storage affects its smallest values and number of distinct values. The measured comparison is descriptive. Attention distributions, matrix ranks and magnitude ranges do not independently identify every cause of failure.

All original candidate files remain unchanged. There were no new paid model calls, no optimization steps, no gradients and no generated reference-model text. The study ran on CPU with one Torch thread. The reference checkpoint file is about 28 MB and is pinned to the revision above. Every local generation is cached by checkpoint hash, prompt, seed and complete decoding settings.
