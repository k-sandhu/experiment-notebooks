## Live collection steps

A new collection should go into a new folder so that this archive and its spend counter stay intact. Copy the
notebook, both requirements files, `tasks.json`, `calendar_seed.sql`, `calendar_initial_events.json`, `finqa/`,
`sources/` and the provenance and version JSON files. Start with empty `cache/` and `episodes/` folders and omit the
old manifest, collection index, restart-point files and derived tables. Then, from the new folder:

```powershell
git clone https://github.com/huggingface/OpenEnv.git data/tmp/OpenEnv
git -C data/tmp/OpenEnv checkout 21fbb0ecb2a3e74110b59cf38a1b195decc75c88
python -m pip install -r requirements-live.txt
python -m pip install --no-deps -e data/tmp/OpenEnv/envs/calendar_env -e data/tmp/OpenEnv/envs/finqa_env -e data/tmp/OpenEnv/envs/repl_env
```

The Calendar package has nested source modules, so use the editable install of the pinned checkout rather than a
wheel. Sign in to `codex`, set `OPENROUTER_API_KEY` in the environment (never in a notebook cell), change the
protocol name, set `NB25_LIVE=1` and run the notebook. Completed cache entries are reused; an incomplete request
record stops the run rather than being sent again. Each paid request is reserved against the dollar and call caps
before it is sent. The cache key covers the full request, model identifier, provider settings, sampling identity,
protocol and CLI settings; API keys and authorisation headers are never saved. The worked examples and the narrative
describe this frozen run and must be re-selected and rewritten for a new collection.
